## 一、技术维度

**掌握最扎实的**：

1. **数仓分层与建模**：从 ODS 贴源到 DWD 星型模型再到 DWS/ADS 集市，真正理解了"分层解耦、口径唯一"的意义——所有指标从 DWD 一处计算，上游变了只改一层；
2. **数据清洗的工程化**：三站分层管道（枚举→异常格式→拆分合并）让清洗过程可回溯。"大额断档不做伪还原、留痕隔离"这类决策比"能跑就行"重要得多；
3. **踩坑排障能力**：回收站陷阱（DROP PURGE）、动态分区上限、Metastore 端口探活、Superset CSRF 轮换、ECharts 源码内含 `</body>` 截断 HTML 等，每个坑都变成了部署手册里的"常见问题"。

**仍需加强的**：

1. 对 Hive 调优（内存/并行度）只停留在分区裁剪层面，EXPLAIN 计划的深入解读还不够；
2. LangChain 的链路编排会用但不深，Prompt 工程的系统性方法论欠缺；
3. ClickHouse 只完成了接入部署，还没有真正把它用到加速场景。

## 二、协作维度

1. **Git 协同**：第 3 周的"双分支 + 真实合并冲突"演练价值最大——冲突解决不是背命令，而是理解"谁的时间线是对的"；PR/Review 留痕让协作过程可审计；
2. **分工与文档**：四大文档（需求/清洗/架构/部署）由不同角色主笔再交叉校对，体会到"口径统一"不仅是数据口径，也是文档口径——指标定义一处改动要同步多处；
3. **沟通效率**：AI 协同日志让我们把"和 AI 怎么配合"显性化了，12 问实测、批判性反思这些过程记录下来，复盘时才发现 AI 也会犯口径错误，人的审核不可省。

## 三、表达维度

1. **答辩表达**：准备 10 分钟演示时最大的教训是"先讲业务价值，再讲技术亮点"——评审关心系统解决了什么问题，而不是堆了多少组件；演示脚本按"数据链路→数仓→预测→问答→大屏→一键部署"走一遍，时间刚好；
2. **文档写作**：从第 1 周的流水账笔记到第 5 周的结构化文档（口径表、对账公式、修复率），学会了"每个数字都能追溯到一次实跑"的写法；
3. **改进计划**：把大屏和仪表板录一段备用视频，防现场环境翻车；英文 README 之后再补一次开源发布流程实践（LICENSE、CHANGELOG、Release）。

## 四、一句话总结

五周下来最大的收获不是"会用 Hive"，而是完成了从"写 SQL 的人"到"能交付一个可复现、可追溯、可展示的数据系统"的转变。
